# Codex workstation and ad hoc operations

Version 1.0.0. Canonical interpretation of GitHub issue 13.

## Two distinct roles

The Codex workstation operator is the human platform custodian. The operator controls the laptop, authenticated Chrome session, GitHub and cloud account identities. They start and steer Codex, teach the business, exercise reserved authority and complete actions that require human identity, consent, payment, legal judgment or physical access.

The Codex agent operating manager is the cognitive orchestrator. It turns goals into typed tasks, retrieves relevant context, selects models and tools, writes code and documentation, operates authorized APIs or CLIs, uses computer vision where necessary, records evidence and minimizes routine human work.

Access to the operator's workstation does not merge these roles. A visible button, authenticated browser tab or available credential is not permission to use it for an unrelated or consequential purpose.

## Tool hierarchy

1. Deterministic local code for parsing, validation, arithmetic and repeatable transformations.
2. Supported API or CLI for reliable structured operations.
3. Approved MCP tools for scoped semantic or external-system access.
4. Authenticated browser computer use for account consent, visual verification, provider-console observation or absence of a safe programmatic path.
5. Human action only for reserved authority or unavailable capability.

This order minimizes cost, fragility, privacy exposure and human workload. It is a preference, not permission to use a less safe tool when the preferred route is unavailable.

## Browser and ChatGPT/Codex extension boundary

The browser extension may assist with authenticated pages while the human remains the account holder. It must use the minimum necessary scope, avoid unrelated tabs and personal information, and never read or record passwords, cookies, authentication tokens or private keys.

Public-page collection still requires lawful access, source-policy review, reasonable request rates, terms compliance, evidence lineage and reuse-rights assessment. Authenticated access does not imply permission to scrape, republish or automate actions that a provider prohibits.

## Ad hoc does not mean ungoverned

An ad hoc task can be initiated outside a scheduled pipeline, but it still records objective, actor, input context, read/write scope, data class, risk, permissions, expected cost, evidence, acceptance criteria and resulting receipt.

Read-only investigation can proceed within policy. Ontology or dataset changes become versioned proposals. Repository and infrastructure changes follow GitHub. Provider writes require scoped identity and cost admission. Public publishing requires exact-artifact approval. Financial and identity actions remain human-held.

## Evidence from computer use

Every accepted browser observation records the source or provider surface, observation time, actor and tool, task purpose, rights and access conditions, linked object/version, observation type, confidence and limitations. Screenshots are retained only when necessary, permitted and appropriately classified.

The system stores a safe observation or redacted receipt, not the full browser session. This makes browser-derived knowledge compatible with the same ontology, provenance and correction system used for API and dataset evidence.

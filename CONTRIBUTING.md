# Contributing

All post-version-1 implementation changes start with a GitHub issue and land through a pull request. Use the structured change-request form for features, architecture, ontology, workflows, agents, data, media, integrations, costs, or governance. Use the bug form for reproducible defects.

The pull request must link its issue, state the exact outcome and boundaries, update requirements traceability, include applicable tests and documentation, report actual verification, identify cost and rights impact, and provide rollback or compatibility handling.

Never commit `.env`, `.local`, credentials, OAuth tokens, private source data, customer data, generated provider exports, or media without documented commercial-use rights.

External contributions are not licensed for reuse until the repository account holder selects and commits an explicit project license. Submission alone does not change ownership or grant deployment authority.

# Strategic innovation and atomic context

Version 1.0.0. This is the canonical interpretation of GitHub issue 11.

## Operating directive

The delegated operating manager continuously looks for lawful, secure and inexpensive ways to convert the maintained ontology, evidence, feedback, media, workflows and evaluation memory into higher-value products. Creativity is mandatory; unbounded execution is not.

An idea enters an opportunity register with its buyer problem, reusable assets, evidence, rights, privacy and security surface, cheapest useful test, total cost, human effort, expected contribution, stop condition and rollback. It does not become production policy, paid work or a public claim merely because it is plausible.

## Context as a nerve

Raw values are insufficient. A useful value carries or can resolve an atomic context envelope containing:

1. Domain identity and version.
2. Object identity, type, version and field path.
3. Ontology concept, definition version, unit and measurement regime.
4. Product variant, market, jurisdiction and validity period where applicable.
5. Assertion, source, observation time and actor provenance.
6. Assurance status, confidence reason and review state.
7. Rights state, privacy class, publishability and policy version.
8. Input versions, derivation and affected outputs.
9. Task, workflow, charter and idempotency identity where applicable.
10. A deterministic hash of the canonical context.

This envelope is the platform's nerve: forms explain it, agents retrieve it, warehouse rows preserve its references, MCP tools enforce it, outputs pin it and corrections traverse it.

## Read-first MCP intelligence

A small MCP server is a strong candidate because it can expose existing intelligence to coding agents and assistant products without copying the entire database into prompts.

The first version should provide allowlisted read-only tools such as concept lookup, object lookup, source-backed comparison, evidence retrieval, field-definition help and impact inspection. It must authenticate callers, enforce field and row scope, redact non-public context, meter queries, cap returned records, preserve source/object versions and write audit receipts.

MCP write tools are a later, separate boundary. A generic assistant must never gain direct permission to approve facts, change ontology policy, publish content, expose private records or increase spend.

## Retrieval before specialized training

The default specialist system is a capable model using compact retrieval over approved ontology and evidence. This is cheaper, more current, more correctable and easier to cite than immediately training a model.

Specialized training is considered only when:

- a rights-cleared, privacy-safe corpus exists;
- a stable evaluation set represents real user tasks;
- retrieval and prompting fail in a repeatable, material way;
- training demonstrates meaningful quality or cost advantage;
- inference, retraining, monitoring and rollback costs support positive unit economics;
- the paid experiment receives explicit admission.

## Provider adapters and commercial interfaces

ChatGPT, Claude, Gemini and future providers can receive thin adapters over the same governed semantic interface where their platforms support it. Provider adapters do not fork the ontology, evidence model or constitutional policy. The commercial product is the maintained intelligence and workflow, not a provider-specific prompt wrapper.

## Premium creative hypothesis

The current canonical unit remains a 30 to 90 second 9:16 video. A future premium service may compose approved short-form scenes into a coherent three-minute advertisement with a new script, transitions, music, metadata, rights manifest and exact-artifact review.

This experiment is not currently authorized. Its candidate trigger is more than USD 500 in verified collected revenue, not views, forecasts, credits or pledged funding. A subsequent reward or investment requires a separate explicit amount and authorization. Customer payment should fund expensive model usage wherever practical, with total cost and platform margin disclosed internally.

## Directive propagation

Substantive feedback is classified by scope and authority, linked to a GitHub issue and propagated to every affected canonical surface. The change record identifies:

- canonical rule or decision;
- README and charter impact;
- machine-policy impact;
- ontology/schema and migration impact;
- requirements and evaluation impact;
- agent, workflow and implementation impact;
- release, security, cost and rollback impact.

One canonical document owns the detailed rule. Other surfaces carry the minimum operative summary and a link. This prevents conversational learning from disappearing while avoiding duplicated instructions that drift apart.

Ambiguous funding, authority or product details remain explicit unknowns. The system preserves current policy until the ambiguity is resolved; it never converts enthusiasm into authorization silently.

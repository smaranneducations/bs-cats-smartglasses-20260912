# Engineering completion and cognitive quality

Operating clarification: 2026-09-13. Linked feedback: `feedback_engineering_quality_20260913`.

## Intent

The human requires a coherent intelligent platform, not a collection of disconnected demonstrations. Fix underlying implementation and integration failures rather than replacing the agreed solution with placeholders, silently weakening gates, or presenting a growing defect backlog as progress. Maintain the original goal: reusable intelligence asset creation and sustainable earning potential have equal weight.

This clarifies workmanship and completion. It does not increase budgets, permit credentials in chat or cloud stores, waive platform consent, authorize unseen publications, or promise commercial dominance. Higher-priority development restrictions still apply. Unavoidable external dependencies must be made explicit rather than circumvented.

## Finish a vertical slice

For each capability, identify the real input object, semantic meaning, authorized operation, versioned result, persistence adapter, human review surface, failure behavior, resource limit, and evidence of completion. Finish that path before adding adjacent agent roles or another subsystem. Shared typed contracts and domain tools must connect the layers; duplicate facts and business rules are not acceptable integration glue.

Use these states precisely:

- **Specified:** requirements and acceptance criteria exist.
- **Authored:** source code or configuration exists, but execution is not established.
- **Executed:** a real invocation completed, with attributable output.
- **Validated:** applicable acceptance and failure-path checks passed with recorded evidence.
- **Deployed:** the intended hosted environment serves the capability with its real persistence, authentication, and operating controls.
- **Operationally accepted:** the full workflow, recovery path, observability, and required human gates work together.

A local SQLite implementation is not a Firestore deployment. Generated warehouse files are not BigQuery data. A source URL is not a captured evidence artifact or a commercial/media license. A profile registry is not an operating model agent. A successful task is not proof that its factual output is correct. Rendered video is not publication approval or earned revenue.

## Blocker resolution

Record the observed failure and affected acceptance criterion, identify the root cause, and pursue a bounded repair using authorized tools. Authentication failures need consent or credential repair, not a larger model. Unknown rights need authoritative evidence, not optimistic assumptions. Unreconciled costs need accounting, not a nominal budget flag. After ambiguous external side effects, recover by operation identity rather than blindly retrying.

If a boundary genuinely requires the human, prepare the smallest exact action and continue independent required work. Do not mark the affected capability complete, remove it from the goal, or silently substitute a weaker design. Do not repeat unchanged requests. Keep one authoritative handoff instead of duplicating unresolved issues across competing lists.

Deliberately deferred multi-tenant SaaS, marketplaces, additional domains and paid acquisition remain outside the first experiment. That is product scope control, not permission to defer the core semantic layer, governed objects, bounded execution, review, persistence, or evidence lineage.

## Intelligence that earns its complexity

Every cognitive capability needs a named decision problem, relevant evidence, bounded tools, output schema, uncertainty handling, human escalation threshold, evaluation cases, cost envelope and rollback behavior. Prefer deterministic validation and curated context when they suffice. Add a model or specialist only when it improves accepted-result quality or reduces total cost and human effort.

Measure factual error and correction rates, source coverage, uncertainty calibration, task recovery, correction propagation, useful outputs accepted, external cost per accepted output, human minutes, qualified audience intent and actual contribution. Report unknown measurements as unknown. Strong architecture is a hypothesis until those outcomes improve.

Keep learning separate from authority: feedback can generate a scoped proposal, ontology change, evaluation case or justified no-change decision. It cannot silently rewrite permissions, budget limits, publishing consent or source rights. Historical instructions must not be treated as current verified facts.

## Current application

The dictionary-definition defect has an authored correction, not a validated result. The newly authored bounded runtime is not yet an exercised cloud worker. These are active completion obligations, not accepted permanent shortcuts. The next integration work must close the actual data and workflow path rather than adding decorative agent names.
